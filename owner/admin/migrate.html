Timbered — Data Migration

One-time tool to seed Firestore from WooCommerce data. Run each step once.

Step 1 — Seed products collection

Fetches all published WooCommerce products and writes each to Firestore products/{product_id} with name, image_url, drawing_url, stock_qty, dimensions, and material attributes.

Step 2 — Seed order_phases collection

Fetches all processing WooCommerce orders and writes each line item's tg_phase to Firestore order_phases/{order_id}_{line_item_id}. Only writes items that already have a tg_phase set.

Step 3 — Seed bom field on products

Matches each product in the BOM sheet to a Firestore products document by name, then writes the parts list as a bom array field. Uses qty-per-product (not total qty). Safe to re-run — overwrites only the bom field.

Step 4 — Migrate all products to products_v2

Reads all products docs and maps them to the new bilingual v2 schema, writing to products_v2/{product_id}. For each product whose name matches a BOM_DATA entry, also writes the parts to the parts sub-collection. Skips products that already exist in products_v2 unless "Overwrite" is checked — so product 16154 (which was hand-migrated) is safe by default.

Step 6 — Full order_phases migration (all statuses + history)

Fetches all WooCommerce orders regardless of status, then writes every line item to order_phases/{order_id}_{item_id} with wc_status and a history array seeded from the current tg_phase meta value. Items without a tg_phase are skipped. Safe to re-run — overwrites existing docs.

Step 5 — Seed phase_groups collection

Writes all 8 phase groups (Order Review, Planning, Production, Dispatch, Repair, Interface, Warehouse, Delivery) to phase_groups/{id} in Firestore. Each document stores the group label, color, display order, and the full phases array. Safe to re-run — overwrites the document entirely. This becomes the central source of truth for all WIP phases.
